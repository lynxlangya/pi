# pi-ai 调试指南（真实 DeepSeek + Chrome DevTools）

> 配合 [阅读顺序](./pi-ai-阅读顺序-261107.md) 使用：读完一步，就跑一次脚本，看这一步对应的日志，或者在那里打断点。

## 快速开始

在仓库根目录执行：

```bash
node learning/debug/deepseek-debug.ts
```

```bash
node learning/debug/deepseek-debug.ts tool
```

```bash
PI_LEARN_DEBUG=verbose node learning/debug/deepseek-debug.ts tool
```

| 场景 | 做什么 | 重点看 |
| --- | --- | --- |
| `basic`（默认） | 一问一答，开启思考（`reasoning: "low"`） | 整条链路的顺序、思考字段、usage 解析、`finish_reason` 如何映射 |
| `tool` | 第 1 轮让模型调工具，第 2 轮把工具结果发回去 | `toolcall_start/end`、第 2 轮 `convertMessages` 里 assistant 是否带 `reasoning_content` |

每次运行花费不到 0.001 美元，因为脚本把 `maxTokens` 限制在 1024。

## Key 文件

- 位置：仓库根目录 `.deepseek.env`，格式为 `DEEPSEEK_API_KEY=sk-...`。
- 这个文件写在 `.git/info/exclude` 里（只在本地生效的忽略规则），`git status` 里看不到，也不会被提交。
- 脚本启动时读取它，再设置成 `DEEPSEEK_API_KEY` 环境变量。日志里的 key 都打了码，只显示 `sk-…(35 chars)`。

## 日志开关

| `PI_LEARN_DEBUG` | 输出 |
| --- | --- |
| 不设置 | 什么都不输出。直接运行 pi 或测试时不受影响 |
| `1`（脚本默认） | 关键步骤，见下表 |
| `verbose` | 在 `1` 的基础上，再打印每个原始 SSE chunk 和完整的请求 messages |

日志有两种前缀：

- `[pi-ai:*]`：生产者视角，来自源码里的打点。
- `[consumer]`：调用方视角，是脚本 `for await` 收到的事件。

两者对照着看。生产者往往比消费者快，所以 `[pi-ai:openai] text_start` 可能夹在思考文本的中间打印出来。这正好说明事件先进了队列，消费者稍后才取出来（见 event-stream.ts 的双栈队列）。

## 用 Chrome DevTools 断点调试

1. 启动并停在第一行：

   ```bash
   node --inspect-brk learning/debug/deepseek-debug.ts tool
   ```

2. Chrome 打开 `chrome://inspect`，在 Remote Target 下点 **inspect**。
3. 在 Sources 面板按 `Cmd+P`，输入文件名（比如 `openai-completions.ts`），在下表的行号处打断点，然后按 `F8` 继续运行。
4. 停在断点上时：
   - 在右侧 Scope 里看变量。
   - 在 Console 里可以直接对当前变量求值，比如 `params`、`chunk`、`output`。
   - `[pi-ai:*]` 日志也会出现在 Console 里，里面的对象可以展开。

Node 24 直接运行 `.ts` 时只是把类型标注擦掉，行号不会变，所以 DevTools 里看到的就是源码本身。

建议的断点：

| 断点 | 停下后看什么 |
| --- | --- |
| [models.ts:1000](../packages/ai/src/models.ts:1000) `getAuth` | 认证怎么解析：单步进去看 envApiKeyAuth 怎么读 `DEEPSEEK_API_KEY` |
| [openai-completions.ts:1390](../packages/ai/src/api/openai-completions.ts:1390) `transformMessages` | 第 2 轮时传进来的历史消息 |
| [openai-completions.ts:438](../packages/ai/src/api/openai-completions.ts:438) `retryProviderRequest` | 发请求前的 `params`（完整请求体） |
| [openai-completions.ts:625](../packages/ai/src/api/openai-completions.ts:625) `for await (chunk)` | 每个原始 chunk。建议用条件断点：`chunk.choices?.[0]?.finish_reason` |
| [openai-completions.ts:700](../packages/ai/src/api/openai-completions.ts:700) `ensureThinkingBlock` | 思考增量怎么累积 |
| [openai-completions.ts:760](../packages/ai/src/api/openai-completions.ts:760) `arguments.append` | 工具参数是一段一段拼起来的：看每次 append 之后的部分对象 |
| [openai-completions.ts:659](../packages/ai/src/api/openai-completions.ts:659) `mapStopReason` | finish_reason 怎么映射 |

想用 VS Code 调试也行：在 VS Code 的 JavaScript Debug Terminal 里运行同一条命令，断点打在编辑器里。

## 可以动手做的实验

- **看重试**：在 `.deepseek.env` 里临时把 key 改错一个字符。401 不可重试，会看到 `[pi-ai:retry] 不再重试`，然后是 `失败结束`，`[consumer]` 收到的是 `error` 事件而不是异常。实验完记得改回来。
- **看跨模型清洗**：在 `tool` 场景里，把第 1 轮结果的 `model` 字段改成别的值，再发第 2 轮。会看到 `[pi-ai:transform] 丢弃别家模型的思考块`，第 2 轮的 `reasoning_content` 也变成"无"。
- **看孤儿工具调用**：第 1 轮之后不加 toolResult，直接再追加一条 user 消息。会看到"补一条合成结果"。
- **看 onPayload**：在脚本的 `requestOptions` 里加 `onPayload: (p) => { console.log(p); }`。不改源码就能拿到完整请求体。

## 清理

- 所有打点都调用 `learnLog` 或 `learnVerbose`，用 `grep -rn "learnLog\|learnVerbose" packages/ai/src` 能全部找出来。
- 这两个函数和 `learnMaskHeaders` 定义在 [diagnostics.ts](../packages/ai/src/utils/diagnostics.ts) 的末尾。没有单独建文件，是因为 `npm run check` 限制 models 入口的依赖图最多 20 个文件，新建一个文件就超了。
- 要撤掉打点：`git diff` 能看到全部改动，删掉对应的行即可。
