# 一次回车的完整旅程：从编辑器到屏幕出字

> 学习方法：每次只追一个在 pi 界面里看得见的现象，顺着这张图找到对应的代码。数据（jsonl / json 事件流）回答不了的时候才打断点。
> 行号基于 `feat/learn` 分支（2026-11-09），带 `注：` 批注的文件行号会随批注漂移，对不上时搜函数名。

## 前端经验对照

| 你熟悉的 | 在 pi 里对应的 |
|---|---|
| 点击按钮 | 在编辑器里按回车 |
| 事件处理函数 | `interactive-mode.ts` 的 `onSubmit` |
| 状态管理（store / action） | `AgentSession` 和 `Agent`，把动作广播成 `AgentEvent` |
| `fetch` | pi-ai 的 `streamSimple`，往下到 `openai-completions.ts` |
| Network 面板 | `learning/debug/runs/*.jsonl` |
| Redux DevTools 的 action 日志 | `pi --mode json` 输出的事件流 |
| localStorage | 会话文件 `~/.pi/agent/sessions/` |
| 状态变了就重新渲染 | `message_update` → 组件 `updateContent` → TUI 差量重绘 |

### 容易踩的坑：两条入口在 ⑥ 才汇合

| 谁在调用 | 第 ⑤ 步走哪 |
|---|---|
| pi CLI（`./pi-test.sh`） | `ModelRuntime.streamSimple`（model-runtime.ts:744） |
| `learning/debug/deepseek-debug.ts` | `Models.streamSimple`（models.ts:1084） |

所以跑 pi 时，在 `models.ts` 里打的断点不会停下。两条路在 `provider.streamSimple` 汇合，往下的 ⑥～⑧ 完全一样。

## 每次学习的 5 步

1. **看现象**：在 pi 里做一个动作，盯住屏幕上的一个变化。
2. **先猜**：写一句"我猜它是怎么做到的"。
3. **看数据**：去 jsonl 或 json 事件流里找对应的记录。
4. **数据答不了才打断点**：只打图上的一两个点。
5. **记一句话**：写在下面的"现象清单"里。

## 观察工具

### json 模式：看 pi 本身的事件流

TUI 会占满整个终端，别在 TUI 里开 `PI_LEARN_DEBUG`，日志会把画面打乱。改用 json 模式，事件流和日志分开写：

```bash
PI_LEARN_DEBUG=1 ./pi-test.sh --mode json "杭州现在适合跑步吗？" > /tmp/events.jsonl 2> /tmp/learn.log
```

- `events.jsonl`：`AgentEvent` 流，相当于 action 日志。
- `learn.log`：pi-ai 里的 `learnLog` 打点。

待确认：文档说 json 模式的 stdout 只放 JSONL，但 `learnLog` 用的是 `console.log`。第一次跑完先看它有没有混进 `events.jsonl`。

### 断点调试 pi 本身

`pi-test.sh` 的最后一行是用 `--import` 加载源码解析器来启动 `cli.ts` 的。加上 `--inspect` 即可：

```bash
node --inspect --import "file://$PWD/packages/coding-agent/src/experimental/source-resolver.ts" packages/coding-agent/src/cli.ts
```

在仓库根目录运行，然后打开 `chrome://inspect`。建议在 ①④⑧⑪ 各打一个断点，第一次先完整走一遍，不单步进细节。
